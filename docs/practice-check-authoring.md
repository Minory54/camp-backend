# Как создавать задания и писать `test_js`

Документация для текущего тренажёра Camp. Примеры используют его реальный механизм проверки: синхронный JavaScript в Chromium. Они не требуют изменения backend.

**Если задание требует результат — проверяйте результат; если оно обучает конкретному способу записи — дополнительно проверяйте исходный код.** «Сделай текст красным» и «Запиши красный цвет в HEX» — разные задания и разные проверки.

## 1. Как выполняется проверка

`Practices.test_js` содержит **тело функции**, а не модуль и не набор тестов Playwright. Runner фактически выполняет:

```js
new Function('sourceFiles', test_js)(sourceFiles);
```

Перед этим он открывает страницу ученика и добавляет её CSS. Минимальная самостоятельная проверка:

```js
// test-js: minimal
const heading = document.querySelector('h1');
if (!heading) throw new Error('Добавь заголовок h1');
if (!heading.textContent.trim()) throw new Error('Добавь текст в заголовок');
```

Без исключений — задание пройдено. `throw new Error('...')` отклоняет решение и показывает сообщение. `return false` и `return { passed: false }` **не отклоняют** решение: возвращаемое значение игнорируется.

| Инструмент | Для чего использовать |
| --- | --- |
| `document`, `window` | DOM открытой HTML-страницы |
| `querySelector`, `querySelectorAll` | Элементы, количество, вложенность |
| `getAttribute`, `textContent` | Атрибуты и текст |
| `getComputedStyle(element)` | Итоговый стиль после каскада и наследования |
| `document.styleSheets` | Разобранные браузером CSS-правила |
| `sourceFiles` | Исходные тексты файлов ученика |
| `CSS.supports(property, value)` | Распознаёт ли браузер значение свойства |

`sourceFiles` — массив такого вида:

```js
[
  { filename: 'index.html', language: 'html', code: '<h1>Привет</h1>' },
  { filename: 'style.css', language: 'css', code: 'h1 { color: red; }' }
]
```

Находите файл по **имени и языку**, а не по позиции в массиве. Если файл не прислан при текущей проверке, backend использует последнее сохранение ученика, а при его отсутствии — стартовый код практики.

Основная страница — `index.html`. Если его нет, выбирается HTML-файл с наименьшим `Practice_files.id`. У задания только с CSS открывается пустой документ. Все CSS-файлы добавляются отдельными `<style data-filename="...">`, даже если HTML уже подключает их через `<link>`. Поэтому количество `document.styleSheets` не обязано совпадать с количеством файлов, а работающие стили сами по себе не доказывают наличие `<link>`.

### Ограничения текущего запуска

- Разрешены файлы `html` и `css`. Ученические `<script>` и обработчики событий блокируются политикой страницы. Задания на выполнение ученического JavaScript сейчас не поддерживаются.
- `import`, `export`, `require`, Node.js API, `test`, `expect`, `page` не предоставляются.
- Проверка должна быть синхронной. Runner не ожидает её `Promise`: проверки в `async`, `setTimeout`, `fetch` и обработчиках событий могут не повлиять на зачёт.
- Общий лимит — 5 секунд, включая открытие браузера и страницы. Не используйте ожидания и долгие циклы.
- Внешние запросы блокируются. Изображения и внешние шрифты не загружаются. Для `<img>` проверяйте тег и атрибуты; `naturalWidth > 0` здесь не подходит.
- Сообщение исключения ограничено 500 символами. Сейчас возвращается только первая ошибка.

Синтаксическая ошибка теста, timeout и сбой запуска считаются системной ошибкой; сервис возвращает HTTP 503. Исключение внутри уже запущенного теста считается неуспешным решением, даже если это ошибка автора: например, обращение к `null.style`. Сначала проверяйте наличие элемента.

## 2. Сначала договоритесь о требованиях

Сформулируйте задание, затем выпишите условия и допустимые альтернативы. Не добавляйте скрытые ограничения.

| Формулировка | Что принимает проверка |
| --- | --- |
| «Сделай `.title` красным» | Нужный итоговый цвет; формат и селектор могут различаться |
| «Задай `color` в правиле `.title`» | Это свойство именно в этом правиле |
| «Задай красный цвет в HEX» | HEX в оговорённом месте + итоговый красный цвет |
| «Сделай отступы 16 CSS-пикселей» | Любая запись, дающая итоговые `16px` |
| «Используй `padding: 16px`» | Конкретное свойство и исходное значение |
| «Ссылка находится внутри `li`» | Любая глубина вложенности |
| «Ссылка — прямой ребёнок `li`» | Только непосредственное вложение |
| «Добавь заголовок» | Как минимум один подходящий заголовок |
| «Добавь ровно один заголовок» | Строго один |

«Любой текст» обычно означает непустой текст после `trim()`. «Красный» уточните как чистый непрозрачный красный, эквивалентный `#ff0000`. «Отступы» уточните как внешние (`margin`) или внутренние (`padding`), и перечислите стороны.

Для HEX определите длину: `#RGB`, `#RRGGBB`, а при необходимости — формы с альфа-каналом `#RGBA` и `#RRGGBBAA`. Регистр букв обычно несущественен. Формы определены в [CSS Color](https://drafts.csswg.org/css-color-4/#hex-notation).

## 3. Вспомогательные функции

В [practice-check.helpers.js](./practice-check.helpers.js) находятся функции для копирования. **Runner не добавляет их автоматически.** В примерах с отметкой «с helpers» сначала вставьте содержимое этого файла в `test_js`, затем код примера. Нельзя импортировать файл внутри `test_js`.

Для короткого теста скопируйте только используемые функции с зависимостями:

| Функция | Назначение / зависимости |
| --- | --- |
| `assert(condition, message)` | Выбросить понятную ошибку |
| `one(selector, message)` | Ровно один элемент; использует `assert` |
| `readFile(filename, language)` | Исходник; использует `assert` |
| `closeTo(actual, expected, tolerance)` | Сравнение чисел с допуском |
| `sameColor(actual, expected)` | Сравнение RGBA-пикселей; использует `colorBytes` и `assert` |
| `allStyleRules()` | CSSStyleRule, включая вложенные блоки |
| `readSimpleCssProperty(filename, selector, property)` | Исходное значение в простом CSS; использует `readFile` и `assert` |

Каждый пример ниже — **отдельное задание**. При объединении используйте один набор helpers и следите за повторными объявлениями `const`.

## 4. Полный пример: семантическая шапка

### Текст задания

В `index.html` внутри `<body>` создайте одну семантическую шапку `<header>`. Прямо внутри неё расположите один логотип `<img>` и одно меню `<nav>`.

У логотипа задайте `src="logo.png"` и непустой `alt`. Прямо внутри меню разместите один `<ul>` с ровно четырьмя прямыми дочерними `<li>`. Внутри каждого пункта должна находиться ровно одна ссылка с `href="#"` и любым непустым текстом.

Промежуточные обёртки между `header` и `img`/`nav`, между `nav` и `ul`, между `ul` и `li` не допускаются. Для ссылки достаточно находиться внутри `li`; прямое вложение ссылки в этом варианте не требуется. Другие элементы шапки заданием не запрещаются.

### Правильное решение

```html
<!doctype html>
<html lang="ru">
  <head><meta charset="utf-8"><title>Шапка</title></head>
  <body>
    <header>
      <img src="logo.png" alt="Логотип сайта">
      <nav>
        <ul>
          <li><a href="#">Главная</a></li>
          <li><a href="#">Каталог</a></li>
          <li><a href="#">О проекте</a></li>
          <li><a href="#">Контакты</a></li>
        </ul>
      </nav>
    </header>
  </body>
</html>
```

**Готовое содержимое `test_js`: [practice-header.test-js.js](./practice-header.test-js.js).** Оно самостоятельно, helpers добавлять не нужно. Проверяет все требования, включая атрибуты и текст каждой ссылки.

Исходный тест Hexlet не проверяет `src="logo.png"`, непустой `alt`, `href="#"` и непустые подписи, хотя они описаны в задании. Наш вариант их проверяет. Требование видимости — отдельное условие: добавляйте его явно, если оно нужно для урока.

### Прямое вложение и любая глубина

```js
header.querySelector('nav');             // nav на любой глубине
header.querySelector(':scope > nav');    // nav — прямой ребёнок header
document.querySelector('header > nav');  // nav прямо внутри какого-нибудь header
```

После поиска шапки ищите меню внутри неё: тест не должен собирать логотип из одной шапки и меню из другой.

Если требуется **прямая** ссылка внутри `li`, замените в готовом тесте `'a'` на `':scope > a'`. Если ещё запрещены дополнительные вложенные ссылки, отдельно проверьте `items[i].querySelectorAll('a').length === 1`. `list.children` считает только элементы: комментарии и переводы строк не мешают.

Для буквального атрибута используйте `getAttribute('href')`, а не `link.href`: последнее возвращает разрешённый абсолютный URL. Аналогично, `img.src` не подходит для точного сравнения с `logo.png`.

## 5. Цвет: принимать разные способы записи

Задание: «Сделайте текст единственного `.title` чистым непрозрачным красным. Способ задания цвета свободный».

Каждый вариант подходит, если даёт итоговый красный:

```css
.title { color: red; }
.title { color: #f00; }
.title { color: #FF0000; }
.title { color: rgb(255, 0, 0); }
.title { color: rgb(100% 0% 0%); }
.title { color: hsl(0 100% 50%); }
.title { color: rgba(255, 0, 0, 1); }
:root { --accent: red; }
.title { color: var(--accent); }
```

Наследование и inline-стили допустимы, если способ не ограничен. Если `.title` несколько, проверяйте каждый либо явно потребуйте один, как здесь.

Проверка с helpers:

```js
// test-js: red-result
const title = one('.title', 'На странице должен быть один элемент .title');
assert(sameColor(getComputedStyle(title).color, '#ff0000'),
  'Сделай текст .title чистым непрозрачным красным');
```

Для обычных sRGB-записей достаточно сравнить `getComputedStyle(title).color` с `'rgb(255, 0, 0)'`. Браузер нормализует традиционные цвета; в других цветовых пространствах сериализация может отличаться. См. [MDN: getComputedStyle](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle).

`sameColor` приводит поддерживаемые форматы к RGBA-пикселю Canvas и сравнивает отображение в **8-битном sRGB**, включая прозрачность. Это удобно для учебных цветов, но округляет дробные каналы и не проверяет математическую идентичность цветов или точность широкого цветового охвата. Для таких уроков нужна специальная проверка.

`element.style.color` читает только inline-стиль. Оно не подходит для проверки результата из CSS-файла или наследования.

## 6. Цвет: принимать только HEX

`getComputedStyle` и CSSOM нормализуют значения. По итоговому `'rgb(255, 0, 0)'` невозможно узнать, написал ученик `red`, `#f00` или `rgb(...)`. Даже `rule.style.getPropertyValue('color')` и `rule.cssText` не сохраняют исходный HEX надёжно. Проверяйте **исходник**. См. правила [сериализации CSSOM](https://drafts.csswg.org/cssom/#serialize-a-css-value).

### Задание с однозначными ограничениями

«В `style.css` напишите одно отдельное правило `.title`. Задайте в нём `color` ровно один раз. Используйте непрозрачный красный в HEX из трёх или шести цифр. Текст `.title` должен стать красным. Используйте обычные CSS-правила без `@media`, других `@`-правил, вложенности и CSS escape-последовательностей. Другие обычные свойства и правила разрешены».

Эти ограничения нужны для небольшого исходного анализатора в helpers. Их нельзя молча применять к заданию «любой корректный CSS».

Проверка с helpers:

```js
// test-js: red-hex
const title = one('.title', 'На странице должен быть один элемент .title');
const value = readSimpleCssProperty('style.css', '.title', 'color');
assert(/^#(?:[0-9a-f]{3}|[0-9a-f]{6})$/i.test(value),
  'В color используй HEX из трёх или шести цифр');
assert(sameColor(value, '#ff0000'), 'В HEX задай именно красный цвет');
assert(sameColor(getComputedStyle(title).color, '#ff0000'),
  'Проверь, что итоговый цвет текста .title — красный');
```

Нужны все три условия:

1. Формат отклоняет `red`, `rgb(...)` и `var(--red)`.
2. Значение отклоняет другой корректный HEX, например `#00ff00`.
3. Результат отклоняет запись, переопределённую другим правилом или inline-стилем.

`readSimpleCssProperty` работает с указанным файлом и точным отдельным селектором. Не путает `.title` с `.title-large`, пропускает комментарии, учитывает строки и скобки функций. Разрешает конечный `!important`, отклоняет повторные объявления проверяемого свойства и повторные правила с указанным селектором.

Это **ограниченный анализатор учебного CSS**, не полный CSS-парсер. Он не поддерживает at-rules, вложенность, escape вне строк и произвольные имена свойств: используются обычные латинские имена с дефисами. Для свободного CSS нужен полноценный парсер с исходными диапазонами значений, встроенный в тест, либо расширение runner, передающее такой разбор. Импорт npm-пакета прямо в `test_js` сейчас невозможен.

Тест подтверждает наличие HEX-декларации и итоговый цвет. Он не доказывает, что именно эта декларация победила в каскаде, если другое правило задаёт тот же красный. Запрет всех других способов задания цвета — отдельное требование и отдельная проверка.

### Допустимые формы HEX

| Требование | Регулярное выражение для исходного значения |
| --- | --- |
| Только 6 цифр | `/^#[0-9a-f]{6}$/i` |
| 3 или 6 цифр | `/^#(?:[0-9a-f]{3}|[0-9a-f]{6})$/i` |
| Все формы, включая альфа-канал | `/^#(?:[0-9a-f]{3}|[0-9a-f]{4}|[0-9a-f]{6}|[0-9a-f]{8})$/i` |

В третьем варианте итоговый непрозрачный красный всё равно отклонит `#ff000080`. `#f00f` и `#ff0000ff` могут пройти, если формы с альфа-каналом разрешены. Не используйте `{3,8}`: оно ошибочно разрешает длины 5 и 7.

| CSS | Свободный красный | Красный HEX из 3/6 цифр |
| --- | --- | --- |
| `.title { color: red; }` | Да | Нет |
| `.title { color: #f00; }` | Да | Да |
| `.title { color: #FF0000; }` | Да | Да |
| `.title { color: rgb(255 0 0); }` | Да | Нет |
| `.title { color: hsl(0 100% 50%); }` | Да | Нет |
| `.title { color: #ff0000ff; }` | Да | Нет |
| `.title { color: #00ff00; }` | Нет | Нет |
| `.title { color: #ff000080; }` | Нет | Нет |
| `/* .title { color: #f00; } */` | Нет, если нет другого красного | Нет |
| `.title-large { color: #f00; }` | Нет, если не применяется к `.title` | Нет |
| `.title { color: #f00; color: blue; }` | Нет | Нет |
| `.title { color: #f00; } .title { color: blue; }` | Нет | Нет |

## 7. Отступы: результат и конкретный способ

### Любой способ получить 16px со всех сторон

«Задайте единственной `.card` внутренние отступы по 16 CSS-пикселей с каждой стороны. Способ записи свободный».

Проверка с helpers:

```js
// test-js: padding-result
const card = one('.card', 'Добавь один элемент .card');
const style = getComputedStyle(card);
for (const property of ['padding-top', 'padding-right', 'padding-bottom', 'padding-left']) {
  const actual = Number.parseFloat(style.getPropertyValue(property));
  assert(closeTo(actual, 16), `У .card ${property} должен быть равен 16px`);
}
```

Пройдут `padding: 16px`, четыре отдельных свойства, подходящий `calc(...)`, логические `padding-block`/`padding-inline`, а также `1rem`, **если** корневой размер шрифта равен 16px.

«Хотя бы один отступ больше нуля» подходит только для задания «добавьте любой ненулевой внутренний отступ». Для требования ко всем сторонам это слишком слабый тест.

### Только `padding: 16px`

«В отдельном правиле `.card` файла `style.css` используйте `padding` ровно один раз со значением `16px`. Ограничения простого CSS — как в HEX-примере».

Проверка с helpers:

```js
// test-js: padding-px
const value = readSimpleCssProperty('style.css', '.card', 'padding');
assert(/^16px$/i.test(value), 'Используй padding со значением 16px');
const card = one('.card', 'Добавь один элемент .card');
const style = getComputedStyle(card);
for (const property of ['padding-top', 'padding-right', 'padding-bottom', 'padding-left']) {
  assert(closeTo(Number.parseFloat(style.getPropertyValue(property)), 16),
    `Проверь итоговый ${property} у .card`);
}
```

`padding: 16px 16px` и `padding: 1rem` дают тот же результат, но не соответствуют этой формулировке. Чтобы принимать `16.0px` или `+16px`, проверяйте число и единицу отдельно.

## 8. Размеры, проценты и единицы

### Итоговая ширина контентной области 200px

В этом варианте задание должно явно требовать `box-sizing: content-box`. Проверка с helpers:

```js
// test-js: width-result
const card = one('.card', 'Добавь один элемент .card');
const style = getComputedStyle(card);
assert(style.boxSizing === 'content-box', 'Для этого задания используй box-sizing: content-box');
assert(closeTo(Number.parseFloat(style.width), 200), 'Ширина контентной области .card должна быть 200px');
```

Для размера всей рамки используйте `getBoundingClientRect().width` и определите, разрешены ли трансформации. Метод включает padding и border и отражает геометрию после трансформаций; см. [MDN: getBoundingClientRect](https://developer.mozilla.org/en-US/docs/Web/API/Element/getBoundingClientRect).

Не путайте «запиши `width: 50%`» и «ширина равна половине родителя». Для первого проверяйте исходник; для второго — геометрию в подготовленной разметке с известными размерами, box-sizing и padding. Проценты зависят от содержащего блока, который не всегда равен непосредственному родителю DOM.

### Только пиксели, с любым положительным числом

Для обычного правила `.card` в `style.css`, с helpers и ограничениями простого CSS из раздела 6:

```js
// test-js: width-px
const value = readSimpleCssProperty('style.css', '.card', 'width');
assert(/^\+?(?:\d+(?:\.\d+)?|\.\d+)px$/i.test(value),
  'Задай width одним неотрицательным числом в px');
assert(CSS.supports('width', value), 'Укажи корректную ширину');
assert(Number.parseFloat(value) > 0, 'Ширина должна быть больше нуля');
```

Пройдут `200px`, `200.0px`, `.5px`, `+200px`. Не пройдут `12rem`, `50%`, `calc(...)`, отрицательное значение и ноль. Это проверка исходного формата, не итоговой ширины; если результат важен, добавьте его проверку.

CSS часто разрешает **ноль без единицы**. Для свободного задания считайте `0` и `0px` эквивалентными; если обязательная единица — цель урока, напишите это прямо.

`Number.parseFloat('16rem') === 16` не доказывает, что размер равен 16px. Используйте его для вычисленного свойства, возвращаемого в px, либо отдельно проверяйте исходную единицу.

## 9. Фон, границы, шрифт и выравнивание

Для результата используйте отдельные вычисленные свойства: так принимаются сокращённые и полные записи.

Задание: «У единственной `.card` сделайте белый фон без фонового изображения, красную сплошную границу 1px со всех сторон, размер шрифта 20px, жирность 700 и выравнивание текста по центру. Способ записи свободный».

Проверка с helpers:

```js
// test-js: appearance
const card = one('.card', 'Добавь один элемент .card');
const style = getComputedStyle(card);
assert(sameColor(style.backgroundColor, '#fff'), 'Сделай фон .card белым');
assert(style.backgroundImage === 'none', 'В этом задании фон .card должен быть без изображения');
for (const side of ['top', 'right', 'bottom', 'left']) {
  assert(closeTo(Number.parseFloat(style.getPropertyValue(`border-${side}-width`)), 1),
    `Задай границу 1px со стороны ${side}`);
  assert(style.getPropertyValue(`border-${side}-style`) === 'solid',
    `Сделай границу ${side} сплошной`);
  assert(sameColor(style.getPropertyValue(`border-${side}-color`), '#f00'),
    `Сделай границу ${side} красной`);
}
assert(closeTo(Number.parseFloat(style.fontSize), 20), 'Размер шрифта .card должен быть 20px');
assert(style.fontWeight === '700', 'Задай жирность шрифта 700');
assert(style.textAlign === 'center', 'Выровняй текст .card по центру');
```

Пройдут `background: white`, `background-color: #fff`, `border: 1px solid red`, отдельные свойства границы, `font-weight: bold` и `font-weight: 700`. Проверяется CSS-состояние, не наличие внешнего шрифта и не пиксельное изображение всей страницы.

Если нужен именно `background-color`, а не `background`, читайте исходную декларацию через `readSimpleCssProperty`. Для урока по сокращённому `border` проверяйте `border` в исходнике, а итоговые стороны — через computed style.

Для семейства шрифта проверяйте заданное семейство/список, а не реально загруженный внешний шрифт. Для `line-height` решите, что требуется: исходный коэффициент `1.5` или итоговый размер. `line-height: normal` нельзя превращать в число через `parseFloat`.

## 10. Flexbox, Grid и конкретный селектор

Задание: «У `.row` включите `display: flex`, расположите элементы строкой, центрируйте по обеим осям и задайте gap 12px».

Проверка с helpers:

```js
// test-js: flex-result
const row = one('.row', 'Добавь один элемент .row');
const style = getComputedStyle(row);
assert(style.display === 'flex', 'Задай .row display: flex');
assert(style.flexDirection === 'row', 'Расположи элементы .row строкой');
assert(style.justifyContent === 'center', 'Центрируй элементы по главной оси');
assert(style.alignItems === 'center', 'Центрируй элементы по поперечной оси');
assert(closeTo(Number.parseFloat(style.rowGap), 12) &&
       closeTo(Number.parseFloat(style.columnGap), 12), 'Задай gap 12px по обеим осям');
```

Если формулировка просто «расположите элементы горизонтально», требование Flexbox — скрытое ограничение: аналогичный результат может дать Grid. Для урока по Flexbox укажите метод.

Для Grid аналогично проверяйте `display === 'grid'`. Для «три равные колонки» проверяйте фактические колонки и геометрию при фиксированном контейнере; для «используйте `repeat(3, 1fr)`» — исходник. Вычисленное значение не обязано сохранять `repeat(...)`.

### Наличие отдельного правила `.card`

Проверка с helpers:

```js
// test-js: selector-rule
const rule = allStyleRules().find(rule => rule.selectorText.trim() === '.card' &&
  rule.style.getPropertyValue('display').trim() === 'flex');
assert(rule, 'Добавь отдельное правило .card со свойством display: flex');
const card = one('.card', 'Добавь один элемент .card');
assert(getComputedStyle(card).display === 'flex', 'Правило должно включить Flexbox у .card');
```

Первое условие проверяет декларацию, второе — результат. `allStyleRules()` обходит вложенные правила, но нахождение правила **не доказывает**, что его `@media`/`@supports` активен или оно победило в каскаде.

Требуется отдельный селектор `.card`: `.card, .panel` не принимается. Для простых разрешённых списков можно сравнивать части `selectorText.split(',')`, но это не универсальный разбор: запятые бывают внутри `:is(...)` и `:not(...)`. Для задания на результат селектор обычно не нужно ограничивать.

## 11. Задания только с CSS

В CSS-only задании `.card` может отсутствовать в DOM. Для простого отдельного класса создайте временный образец. Проверка с helpers:

```js
// test-js: css-only
const probe = document.createElement('div');
probe.className = 'card';
document.body.appendChild(probe);
try {
  const style = getComputedStyle(probe);
  assert(closeTo(Number.parseFloat(style.paddingTop), 16),
    'Задай .card верхний внутренний отступ 16px');
} finally {
  probe.remove();
}
```

Для `.layout > .card`, `:hover`, процентных размеров и других зависимых стилей простой `div` не подходит. Создайте подходящую DOM-структуру с известными условиями. Для интерактивных состояний и нескольких размеров экрана runner понадобятся дополнительные возможности: сейчас размер страницы специально под задание не настраивается.

Если упражнение проверяет только написанное правило, ограничьтесь CSSOM или исходником, явно не обещая проверку внешнего вида.

## 12. Текст, атрибуты, видимость и исходный HTML

- Для «элемент существует» достаточно DOM. Для «ровно один» проверяйте количество: `querySelector` возвращает только первый.
- `textContent.trim()` принимает вложенные `<span>`, но учитывает скрытый текст. Видимый текст — отдельное условие; иногда подходит `innerText`, с оговорками о layout.
- Для «атрибут присутствует» используйте `hasAttribute`. Для «непустой» — `(getAttribute(...) ?? '').trim() !== ''`.
- Для boolean-атрибута `required` проверяйте `hasAttribute('required')` или `input.required`: запись `required="false"` тоже включает его.
- `display !== 'none'` не является полной проверкой видимости: родитель может быть скрыт, размер — нулевым, opacity — нулевой, элемент — перекрытым. Сначала определите нужный смысл видимости.
- DOM не доказывает, что ученик явно написал `html`, `head`, `body`, закрывающие теги или определённые кавычки: браузер дополняет и исправляет HTML. Для таких уроков проверяйте исходник подходящим парсером.
- Поиск HTML-тегов регулярным выражением после удаления комментариев допустим только для ограниченных простых примеров: совпадение может быть внутри строки или текстового содержимого. Это не полноценная проверка синтаксиса документа.

Короткая проверка с helpers:

```js
// test-js: attributes
const input = one('input[name="email"]', 'Добавь одно поле email');
assert(input.getAttribute('type') === 'email', 'Укажи type="email"');
assert(input.required, 'Сделай поле email обязательным');
const link = one('a.help', 'Добавь одну ссылку .help');
assert(link.getAttribute('href') === '#', 'Укажи href="#"');
assert(link.textContent.trim() !== '', 'Добавь текст ссылки');
```

Если требуется подключение CSS через HTML, отдельно ищите `<link rel="stylesheet" href="style.css">`. Работающие стили в Camp этого не доказывают: runner добавляет их самостоятельно.

## 13. Как адаптировать тесты Hexlet / Playwright

Ваш пример запускается в Playwright Test. В Camp Playwright открывает браузер, но **API Playwright Test внутри `test_js` не предоставляется**.

| Внешний Playwright-тест | В `test_js` Camp |
| --- | --- |
| `import { test, expect } ...` | Удалить; использовать обычные функции |
| `beforeAll`, `browser.newPage`, `page.goto` | Удалить; страницу открыл runner |
| `afterAll`, `page.close` | Удалить; браузер закрывает runner |
| `page.locator('header > nav')` | `document.querySelectorAll('header > nav')` |
| `await expect(items).toHaveCount(4)` | `assert(items.length === 4, '...')` |
| `toHaveAttribute('href', '#')` | `assert(link.getAttribute('href') === '#', '...')` |
| `toHaveCSS('color', 'rgb(...)')` | Проверка `getComputedStyle(element).color` |
| `toBeVisible()` | Отдельно определённая проверка видимости; наличие не равно видимости |
| Несколько `test(...)` | Последовательные проверки с разными сообщениями |

В Playwright Test многие DOM-assertions повторяются до timeout. Проверки Camp синхронные, без такого ожидания. Не копируйте асинхронную структуру, рассчитывая на такое же поведение. См. [Playwright Assertions](https://playwright.dev/docs/test-assertions).

Из вставленного кода удаляйте транспортные артефакты: обратные слэши в конце строк и `&#x20;`. В БД должен находиться нормальный JavaScript-текст.

Для результатов каждого условия, ожиданий, действий пользователя и выполнения JS-решений понадобится расширение runner. Примеры документации работают с текущим контрактом.

## 14. Как сохранить проверку

1. Подготовьте текст в `mdx_source`, стартовые HTML/CSS-файлы и `test_js`.
2. Сохраните тело проверки без `import`/`export` в `Practices.test_js` через создание/редактирование практики или seed.
3. Создайте файлы практики с языками `html`/`css`, свяжите практику с уроком через `Lessons.id_practice`.
4. Проверьте решения через `POST /api/practices/check` либо локально через `runPracticeCheck`.

Через JSON не экранируйте код вручную: передайте строку и используйте `JSON.stringify`. Если код записан внутри шаблонной строки JavaScript в seed, обратные слэши регулярных выражений нужно экранировать: `/\s/` в итоговом `test_js` становится `/\\s/` в строковом литерале seed. В самостоятельном JS-файле удвоение не нужно.

Изменение seed не гарантирует обновления уже созданной практики. Убедитесь, что запись БД действительно содержит новый `test_js`. Документация и примеры сами по себе БД не меняют.

### Проверить пример локально без записи в БД

Из корня backend можно запустить готовую проверку шапки на эталоне:

```sh
node --import tsx --input-type=module <<'JS'
import { readFileSync } from 'node:fs';
import { runPracticeCheck } from './src/modules/practices/practice-check.runner.ts';

const testJs = readFileSync('./docs/practice-header.test-js.js', 'utf8');
const item = '<li><a href="#">Пункт меню</a></li>';
const code = `<header><img src="logo.png" alt="Логотип"><nav><ul>${item.repeat(4)}</ul></nav></header>`;
const files = [{ id: 1, filename: 'index.html', language: 'html', code }];
console.log(await runPracticeCheck(files, testJs));
JS
```

Ожидаемый результат — `{ status: 'passed' }`. Замените `logo.png` на `wrong.png`: должен получиться `failed` с подсказкой про `src`. Здесь `import` допустим, потому что это внешний скрипт Node.js, который запускает runner, а не содержимое `test_js`. Нужны установленные зависимости проекта и Chromium для Playwright.

## 15. Как проверить справедливость теста

Для каждого условия подготовьте решение, нарушающее **только его**. Иначе падение не доказывает, что нужная проверка работает.

Матрица для шапки:

- Правильная структура и все атрибуты — проходит.
- `div` вместо `header` — не проходит.
- Обёртка вокруг логотипа или списка — не проходит.
- Три или пять пунктов — не проходят.
- Пустой `alt`, пробелы в `alt`, неправильный `src` — не проходят.
- Нет ссылки, две ссылки, неправильный `href`, пустой текст — не проходят.

Для CSS дополнительно проверьте:

- Разрешённые варианты: HEX/RGB/HSL, shorthand/отдельные свойства, px/эквивалентные rem.
- Правильную декларацию в комментарии или похожем селекторе.
- Повторное свойство или правило, меняющее результат.
- Неподходящий формат при правильном результате.
- Неактивное `@media`, если медиа-запросы разрешены.
- Значение по умолчанию, совпавшее с ожидаемым. Если нужно **явно задать** свойство, одного computed style недостаточно.

**Правильное решение должно проходить, каждая отдельная ошибка — отклоняться, все разрешённые альтернативы — приниматься.**

Для начала используйте [practice-check.template.js](./practice-check.template.js), [проверку шапки](./practice-header.test-js.js) и [вспомогательные функции](./practice-check.helpers.js).
