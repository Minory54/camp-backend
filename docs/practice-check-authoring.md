# Как писать проверки практик

Проверка хранится в `Practices.test_js`. Это **тело синхронной JavaScript-функции**, которую runner выполняет в Chromium после загрузки файлов ученика. Готовый пример для копирования: [`practice-check.template.js`](./practice-check.template.js).

## Что доступно внутри `test_js`

- `document` — DOM основной HTML-страницы. Основной считается `index.html`; если его нет, HTML-файл с наименьшим `Practice_files.id`. Для практики только с CSS runner создаёт пустую страницу.
- `document.styleSheets` и CSSOM — стили всех CSS-файлов практики. Каждый CSS-файл добавляется отдельным `<style>`.
- `sourceFiles` — массив `{ filename, language, code }` с исходным текстом файлов. Языки: `html` и `css`. Если ученик не прислал файл в текущем запросе, здесь будет последнее сохранение либо шаблон из `Practice_files`.

Не используйте `id_practice_file` или порядок `sourceFiles` как смысл задания: ID и порядок могут отличаться между базами. Находите конкретный файл по `filename` и `language`.

## Правила

1. **Сформулируйте отдельное проверяемое условие для каждого требования задания.** При невыполнении выбрасывайте `new Error("Короткая подсказка ученику")`. Если функция завершилась без исключения, практика считается пройденной.
2. **Проверяйте исходный текст, когда важен написанный тег или декларация.** Браузер сам добавляет `html`, `head` и `body` к фрагменту `<h2>…</h2>`. Поэтому `document.querySelector('head')` не доказывает, что ученик написал `<head>`. Используйте `sourceFiles.find(...).code` для таких требований. Если нужна строгая проверка структуры сложного HTML, простой регулярной строки недостаточно: понадобится полноценный HTML-парсер или специально подготовленный тест.
3. **Проверяйте результат через DOM, когда важно наличие элемента или его атрибутов.** Например, `document.querySelector('h1')` или `document.querySelector('a[href]')`. Перед обращением к свойствам найденного элемента проверьте, что он существует.
4. **Проверяйте CSS через CSSOM либо вычисленный стиль.** Для конкретной декларации используйте `CSSStyleRule.style.getPropertyValue('display')`; для фактического оформления существующего элемента — `getComputedStyle(element)`. Поиск только через `cssText.includes(...)` может принять похожее имя селектора или текст комментария. Просматривайте все `document.styleSheets`, а при необходимости — вложенные правила `@media`.
5. **Не рассчитывайте на наличие HTML.** У CSS-only практики `document.body` пуст. Такую задачу проверяйте по CSSOM или `sourceFiles`.
6. **Не рассчитывайте на два файла.** Проверяйте нужные имена и все подходящие stylesheet. Не используйте `sourceFiles[0]`, `sourceFiles[1]` или фиксированное число листов: HTML может сам подключить CSS дополнительно.
7. **Пишите понятные ошибки без готового решения.** Например, `Добавь правило для .card` или `Задай display для .card`. Runner отправит сообщение ученику (максимум 500 символов), поэтому не помещайте туда служебные сведения и полный эталонный код.
8. **Держите тест синхронным и коротким.** Runner не ожидает `Promise`: `async`, `fetch`, `setTimeout` и другие отложенные проверки могут завершиться уже после зачёта. Общий лимит — 5 секунд.
9. **Не используйте Node.js API.** Проверка работает в браузере: `require`, импорт модулей, `process`, Prisma и файловая система backend недоступны. Внешние сетевые запросы заблокированы.
10. **Проверьте тест на трёх вариантах:** правильное решение, пустой/неправильный код и решение, которое выглядит похожим, но нарушает конкретное условие. Для HTML-структуры обязательно попробуйте один фрагмент без явных `html/head/body`.

## Важная особенность нынешнего runner

Синтаксическая ошибка `test_js` и timeout считаются `system_error`. Но **любое исключение после запуска** сейчас считается `failed`, включая ошибку самого теста (`TypeError`, `ReferenceError`). Поэтому проверяйте `null` и доступность данных до обращения к их свойствам и прогоняйте тест на известных правильных примерах. Отдельного `fail(...)` API пока нет; используйте `throw new Error(...)` для ожидаемого отказа.

## Как добавить новую проверку

1. Скопируйте [`practice-check.template.js`](./practice-check.template.js) и замените селекторы, имена файлов, свойства и тексты ошибок согласно заданию. Удалите ненужные блоки HTML или CSS.
2. Сохраните **содержимое файла без `import`/`export`** в `Practices.test_js` через существующее создание практики или seed.
3. Создайте `Practice_files` с языками `html`/`css`, затем свяжите практику с нужным `Lessons.id_practice`.
4. Прогоните проверку на правильном и нескольких неправильных решениях через `POST /api/practices/check`. Для уже существующей практики изменение seed само по себе не обновляет `test_js` в БД — её запись нужно обновить отдельно.
